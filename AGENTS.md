# AETHER Comparative Audit Engine — Agent Guidelines & Memory

This file defines the core architecture, design philosophy, and business rules of the **AETHER BOQ/BOM Comparative Audit Engine**. Any future agent working in this codebase **must** adhere strictly to these patterns to prevent functional drift or cluttering.

---

## 1. Domain & Business Case (The "15-Year-Old" Explanation)

When massive technology projects are build (like high-security server rooms and clouds), two different spreadsheets need to match up perfectly:
1. **The Client BOQ (Bill of Quantities):** This is the "Wish List." The customer's planners write a spreadsheet of what they think they need (e.g., "I need 16 sticks of 64GB RAM and 4 super-fast hard drives"). This spreadsheet can have many different sheets/tabs for various server setups.
2. **The Partner BOM (Bill of Materials):** This is the "Official Invoice." It is generated by logging into professional distributor portals (like HPE or Dell). It contains hyper-precise SKU parts numbers and exact physical attributes directly supported by the physical server hardware.

**The Problem:** Customers make mistakes. They ask for hard drives that don't fit the server slots, cable kits that are the wrong length, or memory sticks that don't match the CPU channels. This comparative audit engine lets engineers compare both files, automatically fuzzy-matches raw human descriptions to vendor SKUs, and reveals every mismatch before ordering.

---

## 2. Dual-Channel Ingestion & Scraping Architecture

To compare these sheets fairly, they are separated into two explicit operational channels:

### 🗳️ Channel 01: Client Request (BOQ Input)
- **Source:** Fragmented primary multi-sheet workbooks uploaded by the client.
- **Nature of data:** Messy, human-written descriptive items (e.g., "HPE Gen11 CPU upgrade loop").
- **Resolution:** Multiple tabs in the workbook correspond to different high-level configurations.

### ⚙️ Channel 02: Manufacturer Portal (BOM Input)
- **Source:** Standalone manufacturer-guaranteed BOM configurator outputs (single sheet).
- **Automation Agent:** A headless browser service simulated using **Playwright** logs directly into locked manufacturer spaces automatically (e.g. HPE Partner Portal), extracts the exact specifications, and loads the official SKU payload into memory.

---

## 3. UI/UX Hierarchy & Context Separation

To keep the workspace clean and intuitive, the views are separated cleanly:

1. **Agnostic Global Overview (Global Tab):**
   - Renders a multi-vendor aggregate view. Does not mix server-specific layout traits into global parameters.
   - Shows cumulative metrics (financial value, total items, drift percentages).
   
2. **Isolated Server Targets (ALPHA-888, DELL-PRO-25, etc.):**
   - Represents specific hardware configurations.
   - Restricts all database matches, licensing constraints, physical chassis heights, and power requirements specifically to that vendor's technical envelope.

---

## 4. Key Interactive Components

- **Fuzzy SKU Resolution Matcher:** Sandboxed algorithm simulating raw descriptive search logs, executing score-based matches (based on Solution Family, Vendor, and Generation) to resolve human notes to database SKUs. Includes automated safety rules to flag non-compatible category overrides.
- **Logical Tree View:** Shows how parts are physically organized from the outer **Server Frame** (Chassis) down to the internal **Processor sockets**, **Memory slots**, and **Drive Backplanes** (Leaf items).
- **Physical Chassis Visualizer:** Displays a gorgeous proportional outline of the rack units so technicians can visually inspect server density.
- **Drift Radar:** Flags positive excess spares or negative shortages line-by-line so users can reconcile deficits immediately.
